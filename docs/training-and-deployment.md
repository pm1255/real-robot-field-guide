# 训练与部署

数据重要，训练和部署方式同样会改变同一批数据的效果。先修复输入输出语义和执行链路，再在固定数据、固定真机协议下比较方法；不能把数据、算法和推理设置同时变化后的提升归因于一个因素。

下列原因分析说明可能产生该现象的机制，是否适用于现场需结合本项证据核查。整体结论见 [核心分析](causes-and-lessons.md#an-01)。

<a id="run-01"></a>
## RUN-01 loss 低，但真机成功率差

- **现象与影响：** 模型能拟合离线动作，实际抓取却偏一点、接触失败或偏差逐步累积。
- **原因分析：** 离线目标衡量特定数据上的预测误差，闭环任务还受接触精度、关键阶段、分布外状态和误差累积影响；部署变化也可能不体现在训练曲线中。
- **先查：** 数据是否准确且覆盖目标条件；观测动作配对、部署预处理、动作映射与执行速度是否一致。
- **处理：** 将训练／验证 loss 与闭环成功、完成时间、介入和失败阶段分别记录。离线误差是诊断指标，不是任务成功证明。
- **验证：** 使用独立、可重复的真机条件比较检查点；先用开发评测选配置，再做最终测试，避免反复拿测试集挑模型。
- **经验总结：** 把 loss 用于拟合诊断，任务成功用独立闭环试验衡量。
- **依据与范围：** [A01](../resources/articles-and-code.md#a01)、[A02](../resources/articles-and-code.md#a02)、[A03](../resources/articles-and-code.md#a03)均讨论拟合与真机表现的差距，个案不构成模型排名。

<a id="run-02"></a>
## RUN-02 数据转换、归一化或 mask 不一致

- **现象与影响：** 离线预测数值合理，部署时方向、幅度或参考点却错了；缺失维度的填充值也可能被当作真实动作监督。
- **原因分析：** 训练与部署采用不同字段、统计量、参考位姿或旋转约定，会改变数值含义；无效维度未屏蔽还会把填充值当作监督。
- **先查：** 原始字段→训练向量→模型输出→反归一化→环境动作的完整路径；核对维度、单位、顺序、参考系、padding 与有效维度 mask。
- **处理：** 保存原始状态和命令，绑定统计量与数据版本。相对实测末端位姿和相对上一条下发命令是不同定义，位置与旋转的重建方法都要对应。
- **验证：** 用真实样本检查变换往返及边界，再核对部署输入输出。往返数值一致只证明转换自洽，还需检查字段确实代表预期物理量。
- **经验总结：** 核对完整变换路径与物理语义，既检查往返自洽，也检查真实字段来源。
- **依据与范围：** 动作契约与机器学习工程建议；[C03](../resources/articles-and-code.md#c03)可作为具体接口参考，不能自动证明任意模型适配正确。

<a id="run-03"></a>
## RUN-03 推理延迟与动作段衔接不合适

- **现象与影响：** 机器人动作段之间停顿，依据过时图像继续动作，或长段开环执行后难以及时纠偏。
- **原因分析：** 采集、通信、推理与调度共同产生延迟；预测时刻和执行时刻分离，过长开环段或不合适的重规划可能延后纠偏。
- **先查：** 图像采集、传输、预处理、推理、返回与执行各耗时；核对训练时间步、动作 chunk 长度、实际执行步数和重规划频率。
- **处理：** 按瓶颈优化推理与通信，明确过时命令和异步结果的使用方式；改变执行策略需单独记录，不能全部记为训练算法收益。
- **验证：** 在固定数据和检查点下，比较真实完成时间、成功、停顿与介入；展示视频应保留或明确标注被剪掉的等待。
- **经验总结：** 固定检查点分开比较执行策略，记录真实耗时、停顿和成功。
- **依据与范围：** [A03](../resources/articles-and-code.md#a03)报告推理／网络停顿，并披露部分演示省略暂停。没有通用最优 chunk 长度。

<a id="run-04"></a>
## RUN-04 多变量变化，无法判断什么有效

- **现象与影响：** 新一轮同时加数据、换夹爪、改学习率和相机，成功率变好却无法判断来源。
- **原因分析：** 数据、硬件、方法和协议同时改变会混淆影响来源；训练波动或检查点选择规则不同也可能造成表面差异。
- **先查：** 对照组的数据清单、预处理、模型、训练预算、检查点选择、执行策略和评测条件。
- **处理：** 先固定一个可复现基线，优先检查数据与接口。可分别比较采样权重、学习率、训练步数、微调范围和增强；变化太多时明确标注为组合改进。
- **验证：** 使用相同测试条件和预先约定的预算，报告失败类型及运行间波动。不要因单个随机种子的一次成功就宣布方法更优。
- **经验总结：** 明确控制变量与选择规则，多因素调整按组合结果陈述。
- **依据与范围：** [A02](../resources/articles-and-code.md#a02)各轮多因素变化、[A03](../resources/articles-and-code.md#a03)评测讨论；公平比较建议不等于需要穷举所有超参数。

<a id="run-05"></a>
## RUN-05 数据、权重和现场版本无法对应

- **现象与影响：** 有模型文件，却不知道用哪批数据、哪套归一化和哪版标定；旧结果无法定位或复测。
- **原因分析：** 产物只靠目录名或记忆关联，缺少稳定实验 ID 和版本清单，后续无法恢复数据、标定、统计量与权重的对应关系。
- **先查：** 代码提交、环境依赖、数据清单与切分、统计量、模型检查点、机器人／相机配置和评测协议是否用同一实验 ID 关联。
- **处理：** 使用 [实验记录](../templates/experiment-record.md)保存产物标识。把预检查与正式训练分开，等待中的阶段明确记“等待”，不填入虚构进度。
- **验证：** 从一次评测记录能定位其检查点，再定位训练配置、数据和现场版本。能打开监控首页不等于曲线中有实际数据。
- **经验总结：** 每次结果能追到模型、数据和现场版本，等待状态与真实进度分别记录。
- **依据与范围：** 通用可追溯性与监控建议，不是已确认的版本丢失事故。

## 监控建议

实际运行任务时，提供团队可访问的监控入口，并验证它显示当前实验的真实数据：采集看有效条数、条件覆盖和数据异常；训练看正式 loss 与检查点；测评看已完成／计划次数及结果。未开始阶段显示等待。

TensorBoard 等页面可辅助查看，但日志与逐次结果仍需归档。本知识库没有提交计算任务，不提供不存在的实验监控链接。
