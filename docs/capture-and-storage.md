# 采集与存储

“USB 掉线”要拆成身份错配、实际断流和软件阻塞。稳定设备命名解决身份，有源集线器改善部分供电问题，但不能增加其上行链路带宽；录制帧率还必须通过实际时间戳验证。

<a id="io-01"></a>
## IO-01 重启后相机身份改变

- **现象与影响：** 腕部画面与桌面画面对调，或同一个配置打开了另一相机；此时设备可能始终在线。
- **先查：** 配置是否直接使用动态 `/dev/videoN`；相机序列号是否唯一；一个设备是否暴露多个视频节点。
- **处理：** 优先使用设备支持的唯一序列号或稳定路径。无唯一身份时可按物理 USB 路径映射，并把固定插口写进工位配置；拔换插口后需复核。
- **验证：** 重启和重新插接后逐一遮挡／识别相机，确认实际画面与模型输入键对应。别只检查路径存在。
- **依据与范围：** [A01](../resources/articles-and-code.md#a01)、[A04 AMD](../resources/articles-and-code.md#a04)。同型号或同序列号增加识别困难，不足以单独证明物理断流根因。

<a id="io-02"></a>
## IO-02 真实断流、设备重连与 USB 链路问题

- **现象与影响：** 设备从系统消失再出现、相机报超时或出现连续数据缺口；可能丢失关键动作阶段。
- **先查：** 对齐相机报错时间与内核日志，查看线缆／接头、供电、集线器、实际 USB 速率及共享上行拓扑。画面停住也可能是应用阻塞，不能先断言硬件坏。
- **处理：** 在其他条件不变时逐项替换线缆、插口或供电方案，按实际带宽评估分辨率、FPS、编码方式；质量与时序也要重新验证。
- **验证：** 用正式采集的多设备负载运行，统计缺口和重连。单相机短预览通过不能证明整套链路稳定。
- **依据与范围：** [A01](../resources/articles-and-code.md#a01)、[A02](../resources/articles-and-code.md#a02)为作者设备上的报告。定位到具体原因需要现场日志和对照。

<a id="io-03"></a>
## IO-03 实际 FPS、时序与观测动作配对不符

- **现象与影响：** 元信息写 30 FPS，实际保存速度不稳定、重复帧多，或图像对应的是动作之后的状态。
- **先查：** 各相机采集时间、机器人反馈时间、动作发送时间、入队和保存时间；区分设备时钟、主机单调时钟与墙钟，先核对时钟关系再算跨设备延迟。
- **处理：** 明确定义每个训练样本是哪个时刻的观测与哪个目标动作；保留原时间戳，记录匹配方法、丢帧与重复帧策略，不靠更改 FPS 元信息“修复”错位。
- **验证：** 检查间隔分布、最长缺口、有效新帧率，并按动作变化对照视频。阈值按控制周期和任务阶段定义，不能只看平均 FPS。
- **依据与范围：** [A02](../resources/articles-and-code.md#a02)报告采集滞后；具体同步诊断和字段设计属于工程建议，未证明任何特定录制器已同步。

<a id="io-04"></a>
## IO-04 录制 I/O 阻塞遥操

- **现象与影响：** 不录制时跟随正常，开启相机／写盘后滞后；录入的示范本身可能变差。
- **先查：** 控制、相机获取、编码和写盘是否共用阻塞循环；记录循环耗时、队列长度、CPU、存储速度与内存变化。
- **处理：** 按瓶颈拆分采集、控制与存储，使用有界队列并明确定义队列满时行为。异步写盘仍要保持时间与样本关联，不能静默丢数据。
- **验证：** 在相同任务下比较录制开关前后时延与示范质量；结束后检查队列是否刷盘、视频和动作长度是否一致。
- **依据与范围：** [A02](../resources/articles-and-code.md#a02)报告相机 I/O 造成其循环滞后；不代表所有卡顿都由写盘引起。

<a id="io-05"></a>
## IO-05 中断、磁盘满与残缺 episode

- **现象与影响：** 目录里有文件、计数也增加了，但视频无法解码、尾部缺动作或索引无法加载。
- **先查：** 最后一次保存是否结束、剩余空间、编码器／写入器退出状态、各字段条数与末尾时间戳。
- **处理：** 将“录制结束”和“保存完成”分开，只有回读检查通过才计为有效；保留异常批次并标明中止原因，不把残缺记录改成成功。
- **验证：** 用目标数据加载器打开整条轨迹，检查必需字段和视频尾部；新软件版本可在不连接机器人的文件层演练中断恢复。
- **依据与范围：** 通用存储与数据完整性建议，不是来源作者或用户现场已确认的事故。

## Linux 上可先做的只读检查

以下命令用于查看设备和存储，不会启动机械臂。不同发行版可能需要安装对应查看工具；部分内核日志需要读取权限。

```bash
lsusb -t
v4l2-ctl --list-devices
ls -l /dev/v4l/by-id /dev/v4l/by-path
journalctl -k --since '15 minutes ago'
df -h
```

没有 `/dev/v4l/by-id` 不等于相机故障，厂商 SDK 相机可能使用不同识别方式。公开问题报告中只保留定位所需的日志，并把设备身份转为可持续对应的代号。
