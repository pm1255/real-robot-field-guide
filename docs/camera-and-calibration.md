# 相机与标定

相机和标定变化会改变模型输入或动作的物理含义。先检查采集与评测配置是否一致，再决定恢复装配、修正映射或重新采数据。以下是通用排查建议，不是现场故障诊断。

下列原因分析说明可能产生该现象的机制，是否适用于现场需结合本项证据核查。整体结论见 [核心分析](causes-and-lessons.md#an-02)。

<a id="cam-01"></a>
## CAM-01 外部相机或底座挪动

- **现象与影响：** 桌上物体没有换位置，图像中的物体和夹爪关系却变了；固定视角数据训练出的策略可能退化。
- **原因分析：** 相机、底座或工位的相对位置改变，会让同一物理状态形成不同像素位置、尺度和遮挡；训练只覆盖原视角时，部署输入就可能超出已学条件。
- **先查：** 相机支架、机器人底座、桌面相对位置，以及变焦、分辨率、镜像、裁剪配置。只确认“还能看见杯子”不够。
- **处理：** 保存工位照片、安装标记和基准图像。需要跨视角部署时，把视角变化纳入数据与评测计划；重做外参不会自动修复不使用外参的图像策略。
- **验证：** 在相同机器人姿态、相同物体摆放下比较最终模型输入，再以固定试验条件核对闭环表现。
- **经验总结：** 把装配关系和图像处理视为数据版本的一部分，先对照基准输入，再判断是否需要跨视角数据。
- **依据与范围：** [A01 Sherry](../resources/articles-and-code.md#a01)公开复盘；装配与版本管理为工程建议，不能推导所有模型都不具备视角泛化。

<a id="cam-02"></a>
## CAM-02 腕部相机支架变化

- **现象与影响：** 腕部相机随手臂运动本来就会改变画面；支架松动、拆装朝向变化才会改变相机相对手腕的关系。
- **原因分析：** 正常腕部随动沿用固定的相机—手腕关系；支架松动或重装会改变这套关系，使相同关节姿态下的观测发生额外偏移。
- **先查：** 同一关节姿态下画面是否与基准一致，线缆是否拉扯支架，连接件是否松动。
- **处理：** 固定安装关系并记录安装版本；若使用手眼变换，核对对应外参。不要为了“保持画面不动”阻止正常腕部运动。
- **验证：** 对比几个可重复姿态的画面及任务关键阶段；需要恢复性能的结论仍要独立真机测评。
- **经验总结：** 固定并记录相机相对手腕的安装关系，按可重复姿态核对，而非要求任务过程中画面静止。
- **依据与范围：** [A01](../resources/articles-and-code.md#a01)、[A02 ggando](../resources/articles-and-code.md#a02)涉及视角与硬件变化；本条支架检查是工程推论。

<a id="cam-03"></a>
## CAM-03 预览清楚，训练输入却丢信息

- **现象与影响：** 原始相机看得到物体，保存后的裁剪把杯柄切掉，或缩放后接触细节不足；也可能手臂、夹爪或操作者遮挡目标。
- **原因分析：** 下游裁剪、缩放可能移除细节，翻转会改变图像关系；遮挡也会让关键关系不可见。原始预览与模型输入不同，预览正常无法证明训练保留了所需信息。
- **先查：** 实际保存图像与送入模型的图像，逐个视角看接近、抓取、接触、释放阶段，检查颜色顺序、镜像与图像键名。
- **处理：** 根据任务调整视角和预处理；只有腕部视角不足时，再评估外部视角的价值。相机数量本身不是质量指标。
- **验证：** 从真实 episode 抽取关键帧，确认目标与夹爪关系仍可辨认；比较模型时控制其他变量。
- **经验总结：** 以实际保存和送入模型的关键帧验收视角，按任务缺失的信息决定如何调整相机。
- **依据与范围：** [A01](../resources/articles-and-code.md#a01)、[A02](../resources/articles-and-code.md#a02)为个案复盘；[C03 RLinf](../resources/articles-and-code.md#c03)固定版本 Piper 环境含中心裁剪和缩放，具体尺寸需以所用版本为准。

<a id="cam-04"></a>
## CAM-04 校准文件丢失或加载错误

- **现象与影响：** 程序找不到文件、要求重新校准，或同一数字对应的实际姿态变化。文件丢失本身不必然立即改变控制器里的物理零位。
- **原因分析：** 临时存储、ID 或挂载变化可能导致文件找不到；若随后使用不同偏置、方向或默认配置，相同数值的物理含义才会改变。文件缺失与映射改变需分别确认。
- **先查：** 区分关节校准、相机内参、相机／手眼外参；核对机器人 ID、文件位置、容器挂载、校验值与实际加载日志。
- **处理：** 优先恢复同一硬件的原版本。必须重标定时遵循对应型号流程，保留新旧版本，不借用另一台机械臂的零位文件。
- **验证：** 比较已知姿态的反馈读数和对应配置。SO-101 校准动作不能照搬 Piper；图像模仿学习也不一定需要显式手眼标定。
- **经验总结：** 先核对实际加载映射并恢复同一硬件的原版本，重标定后重新检查旧数据兼容性。
- **依据与范围：** [A01](../resources/articles-and-code.md#a01)原帖主要丢失的是关节校准文件；[D01 Seeed](../resources/articles-and-code.md#d01)强调同一 robot ID。是否真实改变映射需现场核查。

<a id="cam-05"></a>
## CAM-05 换硬件或重标定后继续用旧数据

- **现象与影响：** 换夹爪、相机、夹爪指尖或重新标定后，旧模型抓取位置偏移；输入和接触几何可能同时变化。
- **原因分析：** 夹爪几何、相机成像或零位映射改变后，同一观测／动作数值对应的接触结果可能变化；旧数据保留了旧装配的经验。
- **先查：** 把硬件、固件、关节标定、相机装配、图像处理、夹爪行程分别列出，避免把所有变化统称为“数据不够”。
- **处理：** 旧数据先保留原版本并标注来源；依据变化决定恢复装配、显式转换、兼容性验证或重新采集，不直接合并不同映射的数据。
- **验证：** 用固定的小规模开发评测检查变化影响，再做正式测试；不是仅用 loss 判断旧数据是否可复用。
- **经验总结：** 硬件变化单独留版本，先验证兼容性，再决定转换、重采或复用。
- **依据与范围：** [A02](../resources/articles-and-code.md#a02)报告换夹爪及重标定后的退化，但其各轮同时改变多个因素，不构成单因素因果证明。

建议随数据保存：机器人身份、装配照片、标定标识与哈希、相机身份与输入配置、软件与固件版本。示例字段见 [采集任务书](../templates/collection-plan.md)。

现场补充：[WIPE-06 擦黑板相机槽位错位](blackboard-wiping.md#wipe-06)记录既有表中 37/70 异常的统计与按 episode 修正方式。槽位循环错位、物理相机移动、同条录像中途变化是三种不同判断；该检查不能证明后两者发生。
