# 数据质量与覆盖

没有脱离部署范围的“最高覆盖度”。先定义要在哪些物体、摆放和场景下完成任务，再统计独立有效示范。数据决定可学习的经验，正确的数据处理、训练和部署决定这些经验能否被利用。

下列原因分析说明可能产生该现象的机制，是否适用于现场需结合本项证据核查。整体结论见 [核心分析](causes-and-lessons.md#an-08)。

现场补充：[相机槽位错位](blackboard-wiping.md#wipe-06)与 [夹爪目标二值化](blackboard-wiping.md#wipe-07)展示数据条数与 loss 无法单独排除的语义问题；[擦拭死角](blackboard-wiping.md#wipe-05)说明如何按接触与覆盖缺口决定补采方向，原因仍需对应现场证据。

<a id="data-01"></a>
## DATA-01 条数多，但覆盖不足或太稀

- **现象与影响：** 只会采集最常见的位置，边缘和特定朝向经常失败；同一场景多录几万帧没有补上缺口。
- **原因分析：** 固定预算扩展到更多条件会降低每种组合的示范密度；相邻帧和重复摆放增加条数，却没有等量增加独立状态。
- **先查：** 位置、朝向、物体实例、背景、光照、起始姿态、关键接触阶段和计划中的组合；统计独立有效 episode，而非只算总帧数。
- **处理：** 先在明确范围内采得准确、足够密，再有计划扩展。按常见条件、关键边界与失败区域分配预算，保留原分布中的正常成功示范。
- **验证：** 画出或列出实际采集条件与每格有效数量，在独立开发评测中看各条件的失败率；覆盖矩阵不是全世界覆盖证明。
- **经验总结：** 相对部署范围统计独立有效条件、密度及组合缺口，再分配补采预算。
- **依据与范围：** [A01](../resources/articles-and-code.md#a01)、[A02](../resources/articles-and-code.md#a02)。作者样本量不能转成其他任务的最低条数标准。

<a id="data-02"></a>
## DATA-02 示范风格冲突或精度不足

- **现象与影响：** 相似画面对应相互不兼容的动作，模型犹豫；操作者反复碰撞、抓高或停顿，也可能被学进策略。
- **原因分析：** 未提供区分条件的不同技巧可能形成难以辨别的动作目标；示范本身的抓取偏差也会成为监督信号。多样性是否有益取决于条件与模型能否区分。
- **先查：** 同一任务是否混入不同技巧却没提供区分条件；检查关键帧、夹爪闭合时机、操作者及批次差异。
- **处理：** 入门阶段先统一可重复的操作规范，抽查后再扩量。确需多种策略时，保留可区分条件并确认模型与数据量支持；多样性本身不是错误。
- **验证：** 按操作者／策略分组复核，在固定场景测试动作稳定性。任务需要的接触等待、稳定保持不能统一当作无效静止删除。
- **经验总结：** 先建立准确、可重复的示范规范，保留必要多样性及其条件，而非盲目扩量或全部删掉。
- **依据与范围：** [A01](../resources/articles-and-code.md#a01)、[A02](../resources/articles-and-code.md#a02)报告具体示范问题；不是所有多峰动作都应被删掉。

<a id="data-03"></a>
## DATA-03 缺少恢复示范

- **现象与影响：** 初次接近正常，一旦抓偏、滑落或对齐偏差，就重复同一个失败动作。
- **原因分析：** 策略的小偏差把系统带到理想示范之外，训练中缺少从这些状态恢复的正确动作，后续决策便可能持续失败。
- **先查：** 数据是否只含理想起点到成功的单一路径；模型实际失败发生在哪个阶段、偏差状态是否在训练中出现。
- **处理：** 在可控的偏差状态下录制专家正确恢复，保留接管边界和结果。失败记录留作诊断，不把错误动作无标签混进常规专家 SFT。
- **验证：** 在预定义的开发恢复条件中比较成功、介入和超时，并保留正常条件测试；最终验收用未参与调参的条件。
- **经验总结：** 按失败阶段采正确恢复动作，明确专家接管与失败记录的不同用途。
- **依据与范围：** [A03 ML6](../resources/articles-and-code.md#a03)讨论恢复覆盖；专家纠正、离线失败数据和在线 RL 不是同一套训练流程。

<a id="data-04"></a>
## DATA-04 标签与结束边界不可靠

- **现象与影响：** 人按了成功键，但物体随后掉落；把准备、摆放或失败重试混入任务动作；短轨迹缺少释放后画面。
- **原因分析：** 人工事件、录制结束和物理任务完成之间存在时间与判据差异；过早结束会丢失滑落等结尾证据，混入准备动作也会改变监督内容。
- **先查：** 成功是否对应明确可观察条件，成功按键时间与视频结果是否一致，失败／中止／异常是否被混用。
- **处理：** 约定任务完成后的观察要求及各结果含义，保留人工确认依据。录制器的结束事件不自动等于任务成功。
- **验证：** 回看轨迹尾部并抽查标签一致性，隔离缺少结尾证据或字段残缺的 episode；标签更正需留记录。
- **经验总结：** 用可观察完成条件定义标签与边界，保留必要尾部证据并抽查。
- **依据与范围：** [C03](../resources/articles-and-code.md#c03)有多种保存模式，成功筛选行为应查所用版本；本条标签流程是工程建议。

<a id="data-05"></a>
## DATA-05 数据切分与测试泄漏

- **现象与影响：** 验证 loss 好看，换天、换物体或换摆放就差；相邻帧被随机分到训练和测试里。
- **原因分析：** 相邻帧、同物体或同场景高度相关，随机切分可能让测试只是在重复训练条件；反复用最终测试选配置也会削弱独立性。
- **先查：** 是否按完整 episode 切分；如果目标是新物体或新场景泛化，还需按物体、场景、日期或批次分组留出。
- **处理：** 固定数据清单与切分版本。开发集用于选择配置和补采，最终测试条件保持独立，不在反复挑选后仍声称是未见测试。
- **验证：** 检查样本来源和分组是否交叉，分别报告分布内与留出条件表现。一次长录制切成多段不自动提供独立场景。
- **经验总结：** 按目标泛化单位分组留出，开发与最终验收分别管理。
- **依据与范围：** 通用机器学习评测设计，结合 [A01](../resources/articles-and-code.md#a01)、[A03](../resources/articles-and-code.md#a03)的场景与评测讨论；不表示已检测出某数据集泄漏。

## 采集矩阵怎么落地

例如“3 个位置区 × 4 类朝向 × 2 个物体实例”形成 24 个计划条件格。这只是规划示例，既不保证每格一条就足够，也不要求穷举所有组合。

1. 写清实际部署中哪些因素固定、哪些允许变化，以及每格的有效标准与计划数量。
2. 使用 [覆盖矩阵](../templates/coverage-matrix.csv)与 [采集记录](../templates/collection-log.csv)关联每条示范，统计计划、有效、剔除与待补数量。
3. 同时看常见条件密度和重要组合缺口；仅“每个因素都出现过”不能证明组合已覆盖。
4. 用开发评测定位失败再补采，保留最终独立测试与数据版本。

“已覆盖格子／计划格子”只对该矩阵有意义；样本质量、时间同步和有效动作语义是计入覆盖的前提。
